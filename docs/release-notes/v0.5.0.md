## Ambient Context MCP v0.5.0

MCP クライアントからのフィードバック (応答の曖昧さ・誤発火・スキーマ未文書化・payload 過大) に応えた応答スキーマの刷新と、内部構造の責務分離リファクタを含む更新。挙動が変わる項目があるので **Behavioral changes** に目を通してから上げてください。

### What's new

- **per-field 機微度の付与**: `ambient_context_poll_events` の各イベントに `payloadSensitivity` (キーごとの sensitivity マップ) と `maxFieldSensitivity` (payload 内の最大機微度) を追加。同じイベントでも「外側 medium / 内側に high が混じる」状況をクライアント側で識別できるようになりました。
- **`policyVersion` をレスポンスに付与**: `get_states` / `poll_events` / `get_policy` のレスポンスルートに `policyVersion` (SHA256 を base64url 切り詰めた 12 文字) を追加。classifications + overrides の組から計算されるので、変化があったときだけ `get_policy` を取り直せばよくなります。
- **`context.all:read` scope alias**: `context.high:read` と同等のフィルタを「全部入り」の名前で指定できるようになりました。デフォルト挙動 (scope を指定しない場合) は変えていません。
- **新ツール `ambient_context_describe_events`**: 全 **34 イベント**の静的スキーマカタログ (event-level / payload key 単位の sensitivity / 説明 / 例値) を返します。スキーマはリリース間でしか変わらないのでクライアント側でキャッシュ可能。日本語 OS では日本語、それ以外では英語の説明文を返します。
- **`ambient_context_poll_events` の summary mode**: `includePayload: false` で `payload` / `payloadSensitivity` を剥がして返します。1 event あたり ~800 bytes → ~200 bytes 程度に縮みます。`maxFieldSensitivity` は保持されるので、「このイベントを high scope で取り直せば追加情報があるか」のヒントは残ります。
- **`media_session_changed.payload.source_kind`**: `music` / `video` / `browser` / `unknown` のヒント値を追加。AppUserModelId のヒューリスティック分類で、クライアントが「これは音楽か動画か」を区別できます。
- **`foreground_changed.payload.category_changed`**: `foreground_changed` イベントに `category_changed` (`"true"` / `"false"`) を追加。category だけ変わったケースを別イベントに分けずに済みます。

### Behavioral changes

1. **per-field scope filter の導入で、`media_session_changed` の `title` / `artist` は `context.medium:read` のみのクライアントには配信されなくなりました。** `media_session_changed.title` / `.artist` 自体が high 機微なので、`context.high:read` (もしくは `context.all:read`) を申告したクライアントだけが受け取れます。これは元々が privacy leak だった挙動の修正です。
2. **`foreground_changed` の発火条件が変わりました**: Win32 hook 由来から、スナップショット tick 差分検出 (process_name または category の変化) に変更。同プロセス内のウィンドウ切替 (VS Code のタブ間、Chrome のタブ間) では発火しなくなります。"アプリ切替頻度" を生イベント数でカウントしているクライアントは観測値が下がります。
3. **`foreground_app_category_changed` は発火しません**: `foreground_changed.category_changed` に統合されました。privacy classification 自体は deprecated note 付きで残り、既存ユーザーが設定していた override は無害化されたまま残ります。
4. **`ForegroundApp.category` の絶対値が `"unknown"` → `""` に変わりました**: 「category 分類なし」の表現を統一しました。category 値を集計しているクライアントは `"unknown"` と `""` のどちらかへ吸い込む必要があります。
5. **summary mode (`includePayload: false`) でも `payload: {}` / `payloadSensitivity: {}` は serialize されます**: 最大圧縮ではなくスキーマ一貫性を優先しました。

### Bug fixes

- **`first_activity_today` が 1 日 1 回に固定されました**: 旧バイナリではプロセス再起動で「今日初の活動」判定がリセットされ、1 日に複数回発火していました。`settings.json` に `transientStateSettings.lastActivityDate` を永続化することで、再起動を跨いで 1 日 1 回に収束します。
- **events.jsonl backfill**: 旧スキーマで永続化されていたイベント (`payloadSensitivity` / `maxFieldSensitivity` が空) を、アップグレード後の最初の Ingest で再計算して書き戻します。最大 24h の post-upgrade leak 窓を塞ぎました。
- **`McpServerHost.WriteDiscoveryFile()` の tool 一覧に `ambient_context_describe_events` を追加**: 実 MCP サーバは attribute 自動登録で 4 ツールを公開しますが、discovery file (`%LOCALAPPDATA%\AmbientContextMcp\mcp-api.json`) 経由で tool 一覧を取るクライアントが古い 3 ツール構成しか見えていなかった問題を修正。

### Requirements

- Windows 10 version 2004 (10.0.19041, May 2020 Update) 以降
- [.NET 8 Desktop Runtime x64](https://dotnet.microsoft.com/download/dotnet/8.0)

### Install

**Claude Desktop の場合 (推奨)**

1. `ambient-context-mcp-v0.5.0.mcpb` をダウンロード
2. Claude Desktop の設定 → 拡張機能 からインストール
3. タスクトレイの `[●] Ambient Context MCP — :37690` を確認、設定ダイアログで送信ポリシーを調整

**Claude Code / その他クライアントの場合**

1. `ambient-context-mcp-v0.5.0-win-x64.zip` を任意のフォルダに展開
2. `ambient-mcp.exe` を起動 (未署名のため SmartScreen で「詳細情報」→「実行」)
3. タスクトレイ → 「Claude Code 用設定をコピー」 → ターミナルに貼り付け

```bash
claude mcp add ambient-context \
  --transport http http://127.0.0.1:37690/mcp \
  --header "Authorization: Bearer <TOKEN>"
```
