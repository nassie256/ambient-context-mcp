## Ambient Context MCP v0.6.0

状態 path (`get_states`) と履歴イベント (`poll_events`) の対応関係の整理、送信設定 UI の再編、診断ログの追加を含む更新。`foreground_title_changed` をはじめとする新しい opt-in 項目と、送信設定 UI の刷新に伴う既存設定の見え方の変化があるので、**Behavioral changes** に目を通してから上げてください。

### What's new

- **`foreground_title_changed` イベントの追加**: フォアグラウンドウィンドウのタイトル (要約 / 原文) が変わった瞬間を履歴イベントとして記録します。v0.5.0 で `foreground_changed` の対象から外れた、同一プロセス内のタブ / ファイル切替もこのイベントで追えるようになりました。`titleSummary` (medium) と `raw_window_title` (high) は payload key 単位の opt-in です。
- **`media.albumTitle` 状態と `media_session_changed` の `album_title` payload**: 再生中メディアのアルバム名を、state とイベント payload の両方で取得できるようになりました。`album_title` は曲名・アーティストと同じく high 機微で、payload key 単位の opt-in です。
- **`displays.*` 状態の出力**: 接続中の各ディスプレイの `deviceName` / `left` / `top` / `width` / `height` / `primary` を state として返します。privacy classification に定義済みだった `displays` path が、実際に値を伴って emit されるようになりました。
- **送信設定 UI のグループ化**: 送信設定ダイアログを「フォアグラウンドアプリ / 作業リズム / メディア / 環境」の 4 グループ・11 項目に再編しました。関連する state path と event path を意味単位でまとめ、チェック 1 つで両方を opt-in できます (旧 UI の 22 項目から 11 項目に集約)。`events.timezone_changed` / `events.display_count_changed` も環境グループからまとめて有効化できます。
- **日本語 UI / ドキュメントの用語統一**: 「前景」表記を「フォアグラウンドアプリ」「フォアグラウンドウィンドウ」に統一しました。MCP API の path 名 (`foregroundApp.*` 等) は変更していません。
- **`ambient_context_describe_events` のカタログ更新**: 新イベント `foreground_title_changed` を加えた **35 イベント**のスキーマを返します。

### Behavioral changes

1. **アプリ切替時に `foreground_changed` と `foreground_title_changed` が同時に発火し得ます**: process / category が変わると `foreground_changed` が、タイトルも変われば `foreground_title_changed` が同じ tick で発火します。前者はアプリ切替、後者はタイトル変更 (タブ切替を含む) の履歴を表します。イベント数を集計しているクライアントは、両方が増える点に注意してください。
2. **新しい path はいずれも既定で OFF です**: `foreground_title_changed` / `displays.*` / `album_title` は medium または high 機微のため、opt-in しない限り MCP 経由では送信されません。
3. **旧 UI で個別に opt-in していた設定の見え方が変わります**: 新 UI は各項目の代表 path (primary path) を基準に ON / OFF を判定します。旧 UI で共有イベント path (`events.media_session_changed` 等) だけを ON にしていた場合、対応するグループ項目が OFF として表示されることがあります。意図する項目を改めて ON にしてください。
4. **診断ログ `app-diagnostics.jsonl` の出力内容を変更しました**: 通常の capture の開始 / 終了ログを廃止し、遅延した capture (`slow`) と例外 (`failed`) のみを記録します。ファイルが 5 MB を超えると `.old` にローテーションします。
5. **設定ウィンドウの再表示時の挙動を変更しました**: 既に開いている設定ウィンドウをトレイから再アクティブ化する際、保存済みの位置へ移動させるのをやめ、現在の表示位置を保ったまま画面内に収める処理のみを行います。

### Bug fixes

- **送信設定の保存で、共有 path を持つ項目どうしが干渉する不具合を修正**: 複数の送信設定項目が同じイベント path (例: `events.media_session_changed`) を参照している場合、一方の項目を OFF にすると、もう一方の項目で ON にしていた送信設定まで取り消されていました。ON の項目すべてが参照する path の和集合を保存するよう修正しました。
- **送信設定の読み込みで、項目のチェック状態が実際の設定とずれる不具合を修正**: 共有 path を参照する項目が、別の項目によってその path が ON になっているだけでチェック済みとして表示されていました。これにより、無編集で保存すると意図しない opt-in が有効化される恐れがありました。各項目の代表 path (primary path) のみでチェック状態を判定するよう修正しました。

### Requirements

- Windows 10 version 2004 (10.0.19041, May 2020 Update) 以降
- [.NET 8 Desktop Runtime x64](https://dotnet.microsoft.com/download/dotnet/8.0)

### Install

**Claude Desktop の場合 (推奨)**

1. `ambient-context-mcp-v0.6.0.mcpb` をダウンロード
2. Claude Desktop の設定 → 拡張機能 からインストール
3. タスクトレイの `[●] Ambient Context MCP — :37690` を確認、設定ダイアログで送信ポリシーを調整

**Claude Code / その他クライアントの場合**

1. `ambient-context-mcp-v0.6.0-win-x64.zip` を任意のフォルダに展開
2. `ambient-mcp.exe` を起動 (未署名のため SmartScreen で「詳細情報」→「実行」)
3. タスクトレイ → 「Claude Code 用設定をコピー」 → ターミナルに貼り付け

```bash
claude mcp add ambient-context \
  --transport http http://127.0.0.1:37690/mcp \
  --header "Authorization: Bearer <TOKEN>"
```
